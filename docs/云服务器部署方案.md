# 云服务器部署方案（草案，待 hanson 确认）

状态：方案，**未购买任何服务器、未做任何部署**。买服务器、买域名属于费用支出，需要 hanson 本人操作或明确批准。

## 目标
用一台国内云服务器替代内网穿透，得到一个固定的 HTTPS 地址，钉钉工作台首页地址只填一次，不再随电脑重启变化。同一套脚本以后可以装到客户自己的云账号里，做成可复制的交付步骤。

## 两类环境
| 环境 | 谁的服务器 | 用途 |
|---|---|---|
| 测试/演示环境 | 我们公司（hanson）租一台 | 钉钉联调、给客户演示、验收 |
| 客户生产环境 | 客户自己的云账号 | 正式使用；数据留在客户自己那里 |

生产环境默认放客户账号，避免我们替客户保管财务数据，也减少隐私和合同责任。

## 推荐配置（测试环境）
- 国内云厂商的轻量应用服务器或云服务器，2 核 4G、40G 以上系统盘、Ubuntu 22.04/24.04。具体价格以厂商官网为准（未核实）。
- 一个域名，例如 `fin.<你的域名>`。服务器在中国大陆时，域名必须先完成 **ICP 备案**才能用 80/443 对外访问，备案通常需要一到几周（以云厂商说明为准）。备案期间继续用内网穿透测试。
- 不想等备案：可选香港地域服务器，免备案；但财务数据出境需要客户和法务确认，**不建议用于真实客户数据**。

## 部署形态
- Docker Compose：`db`（PostgreSQL 16，数据卷）+ `api`（现有 `infra/Dockerfile`）+ `caddy`（自动申请和续期 HTTPS 证书，反向代理到 api）。
- 数据库端口不对公网开放；安全组只放行 22（建议限制来源 IP）、80、443。
- 凭证：服务器上运行隐藏输入脚本写 `.env`（权限 600），与现在 Mac 上的做法一致；不进仓库、不进聊天。

## 一键部署脚本（已写好，未在真实服务器上运行过）
`infra/server/` 下提供：
1. `server-install.sh`：在新服务器上安装 Docker、拉代码、生成 `.env`（随机 JWT_SECRET 和数据库密码）、填域名、启动 compose、执行迁移和种子数据。
2. `backup.sh`：`pg_dump -Fc` 每日备份，保留 7 天；可选上传到对象存储。
3. `update.sh`：发布前自动备份 → 拉取新版本 → 构建 → 迁移 → 启动；失败按 `infra/发布与回滚.md` 回滚到上一版镜像。

## 上线后要改的钉钉配置
- 应用首页地址、PC 端首页地址改为 `https://fin.<你的域名>/?tenant=<企业代码>`。
- 钉钉后台如果要求配置“服务器出口 IP”白名单，填云服务器公网 IP（以后台当前要求为准）。
- `.env` 中 `PUBLIC_BASE_URL` 改为正式域名。
