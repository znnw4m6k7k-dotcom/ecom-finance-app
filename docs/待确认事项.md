# 待确认事项（需 hanson / 客户确认，未确认前按“当前做法”实现）

| # | 问题 | 当前做法（我的假设） | 影响 |
|---|---|---|---|
| Q1 | **本期 AI 业务闭环选什么？** 文档样板是“询盘→报价草稿”，但 Demo 是电商财务，没有 AI 环节。 | 做“月度经营简报”：系统算数字，AI 写解读和风险提示，财务提交、老板审核后推送钉钉。 | 若客户要的是别的 AI 场景（如对账差异说明、导入字段智能映射、异常费用识别），需要换闭环。 |
| Q2 | **有没有真实试点客户？** | 用 Demo 的虚构品牌“麓野”数据做种子数据。 | 真实上线前要换成客户确认过的数据、费率、提成规则。 |
| Q3 | **谁用这个系统？** Demo 合同是“只给老板一个人看、无登录”。 | 改成多账号：老板（审核）、财务（导入/起草）、只读。 | 角色和权限要客户确认；是否需要“运营只看自己店铺”这类数据范围权限。 |
| Q4 | **钉钉测试用哪种通知？** | 默认群自定义机器人（加签），也支持企业内部应用“工作通知”。 | 群机器人最快验证；工作通知要管理员建应用、给 AgentId 和员工 userid。 |
| Q5 | **钉钉里怎么进系统？** | 提供链接入口 + 免登代码（authCode→userid→已绑定账号）。 | 是否要做成钉钉工作台微应用，需要管理员配置应用首页地址，且服务要有公网 HTTPS 地址。 |
| Q6 | **模型选哪家？** | ModelProvider 可配置，预置 DeepSeek、通义千问、Kimi、智谱、豆包的 OpenAI 兼容地址；默认模拟模型。 | 客户需自行签约、提供密钥，并确认数据可发给该厂商（财务数据出域需法务确认）。 |
| Q7 | **数据量多大？** | 前端一次加载全部明细（演示数据约 9 MB，gzip 后约 1 MB）。 | 超过约 10 万单/月需改为服务端聚合 + 分页。 |
| Q8 | **部署方式？** | 单客户独立部署（一套服务 + 一个数据库），保留 tenantId。 | 若要多客户共用一套（SaaS），需另做安全评审。 |
| Q9 | 导出 CSV / 打印是否要审计、是否限制只读账号导出？ | 不限制、不审计。 | 财务数据外泄风险。 |
| Q10 | 导入文件编码 | 只认 UTF-8（含 BOM）和 .xlsx。 | 淘宝等后台导出的 GBK 编码 CSV 会乱码，需另存为 UTF-8 或 xlsx。 |
| Q11 | 简报退回后，AI 重新生成是否覆盖人工修改？ | 重新生成会产生新版本，旧版本保留可查。 | — |
| Q12 | 通知发给谁？ | 群机器人：发到配置的群；工作通知：发给已绑定钉钉的老板和财务（`NOTIFY_ROLES`）。 | — |
| Q13 | 飞书、企业微信版本的优先级和时间 | 只保留接口与能力矩阵，不实现。 | 按客户实际使用的平台排期。 |
