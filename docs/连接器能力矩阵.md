# 办公平台连接器能力矩阵

统一接口：`packages/workspace-connectors/src/types.ts`（`WorkspaceConnector`）。业务代码只依赖这个接口；**三家平台能力不相同，不假装相同**。代码中的矩阵 `CAPABILITY_MATRIX` 与本表一致，并有测试校验。

状态：**已实现未联调** = 按官方公开文档写好并有单元测试（模拟 HTTP），但还没在真实企业应用上跑过；**计划** = 只有接口，调用会报“暂不支持”。

| 能力 | 钉钉（本期） | 飞书 | 企业微信 |
|---|---|---|---|
| 登录 / 身份映射 | 已实现未联调：H5 微应用免登，authCode → `topapi/v2/user/getuserinfo` → userid → 管理员绑定的内部账号 | 计划 | 计划 |
| 应用入口 | 已实现未联调：`dingtalk://dingtalkclient/page/link?url=…` 打开系统页面 | 计划 | 计划 |
| 发送通知 | 已实现未联调：① 群自定义机器人 `robot/send` + 加签；② 工作通知 `topapi/message/corpconversation/asyncsend_v2`（需 AgentId） | 计划 | 计划 |
| 接收事件 / 回调 | 计划（建议用 Stream 模式，无需公网回调地址） | 计划（长连接事件） | 计划（回调需验签解密） |
| 原生审批 | 不计划（审批在我们系统内完成） | 不计划 | 不计划 |

## 数据源能力（智能表 / 知识库 → 工作台，单向）

代码：`PlatformDataSource`（`packages/workspace-connectors/src/types.ts`）、矩阵 `DATA_CAPABILITY_MATRIX`。**平台受限** = 平台官方接口本身不支持，不是我们没做。

| 能力 | 钉钉（本期） | 飞书 | 企业微信 |
|---|---|---|---|
| 读员工已有的智能表 | 已实现未联调：AI 表格 `GET /v1.0/notable/bases/{baseId}/sheets[/{sheetId}/fields]`、`POST …/records/list`（分页） | 计划（多维表格接口最成熟） | **平台受限**：文档接口只能读应用自己创建的文档 |
| 在平台生成模板表 | 已实现未联调：`POST /v1.0/notable/bases/{baseId}/sheets`（在客户建好的空 AI 表格里新建数据表） | 计划 | 计划（应用自建的智能表可读写） |
| 读知识库目录 | 已实现未联调：`/v2.0/wiki/workspaces/{id}`、`/v2.0/wiki/nodes` | 计划 | **平台受限**：未找到开放接口 |
| 读知识库正文 | 已实现未联调：文档块查询 `/v1.0/doc/suites/documents/{id}/blocks`，抽文字（**返回结构待实测**） | 计划（docx raw_content） | **平台受限** |

所有调用都带操作人 `operatorId=unionId`（员工本人在钉钉里能看到的范围）；新版接口 token 放在 `x-acs-dingtalk-access-token` 头。

### 钉钉数据源联调步骤（需要客户管理员）
1. 在已建的企业内部应用里开通 AI 表格（多维表）读写、知识库/文档读权限，发布新版本（权限名称以后台当前显示为准）。
2. 员工在钉钉工作台打开一次系统（免登时自动记录 unionId）；或管理员绑定时传 `unionId`。
3. 情况一：在钉钉新建一个**空**的 AI 表格 → 复制链接 → 工作台「数据源 → 生成模板表」。
4. 情况二：复制已有 AI 表格链接 → 「读取」→ 选数据表和要写入的业务表 → 核对字段对应 → 确认 → 预览 → 同步。
5. 知识库：复制知识库首页链接 → 选数据型/查询型 → 接入。

## 钉钉联调步骤（需要客户管理员）

**方案 A：群机器人（最快）**
1. 在钉钉测试群 → 群设置 → 机器人 → 添加“自定义”机器人，安全设置选“加签”。
2. 把 Webhook 里的 `access_token` 和加签密钥 `SEC…` 填到服务器环境变量 `DINGTALK_ROBOT_ACCESS_TOKEN`、`DINGTALK_ROBOT_SECRET`（不要发到聊天里）。
3. 设置 `CONNECTOR_PROVIDER=dingtalk`、`DINGTALK_NOTIFY_CHANNEL=robot`，重启服务。
4. 审核通过一份简报，确认群里收到消息；页面“通知记录”显示“已发送”且不带“模拟”。

**方案 B：钉钉工作台 H5 微应用（免登 + 工作通知）**
1. 拿公网 HTTPS 地址。固定地址（推荐）：域名托管到 Cloudflare 后运行 `bash infra/named-tunnel.sh fin.<域名>`，地址不变且开机自启；临时：`bash infra/tunnel.sh`（Cloudflare 免费快速隧道，每次重启地址会变，只用于测试）；正式：云服务器 + 备案域名 + 证书。
2. 管理员在钉钉开发者后台创建“企业内部应用”，添加“网页应用”能力：
   - 应用首页地址、PC 端首页地址：`<公网地址>/?tenant=<企业代码>&corpId=$CORPID$`（`$CORPID$` 原样填写，钉钉打开时自动替换成企业 CorpId，无需手工查）
   - 权限：开通“个人信息读权限 / 成员信息读权限”（只用于免登换 userid）和“工作通知”相关权限。权限名称以后台当前显示为准。
   - 可见范围先只加测试人员，然后发布版本。
3. 在服务器上运行 `sh infra/set-dingtalk-app.sh`，录入 CorpId、AppKey、AppSecret（不回显）、AgentId，选择通知方式。凭证只写进 `.env`，不进聊天、不进仓库。
4. 在钉钉工作台打开应用。首次会提示“该钉钉账号未绑定”，并显示钉钉 userid。
5. 绑定：`node apps/api/dist/bind-identity.js <企业代码> <系统账号> <钉钉userid>`（会写审计），或老板调用 `POST /api/v1/connectors/identities`。系统不读取通讯录。
6. 回到钉钉重新打开应用，应自动登录；审核通过一份简报，确认收到工作通知，“通知记录”不带“模拟”。

不在钉钉内打开时（普通浏览器），页面退回账号密码登录。

联调前必须再次核对钉钉开放平台当前文档（接口地址、权限名称可能调整）。
