# 样板说明：哪些直接复用，哪些按新 Demo 替换

样板 = ecom-finance-app（电商财务，2026-11-04 钉钉真机验收）。`infra/new-project.sh` 复制后，新项目第一天就能 build 和跑测试；然后按下表把样板业务换成新 Demo 的业务。

## 通用骨架（保留，只在需要时扩展）
| 位置 | 内容 |
|---|---|
| `apps/api/src/auth/`、`common/auth.ts` | 账号密码登录、JWT、失败限流、钉钉免登（authCode → userid → 已绑定账号） |
| `apps/api/src/audit/` | 审计事件写入与查询 |
| `apps/api/src/connectors/`、`notifications/`、`bind-identity.ts` | 连接器管理、通知投递（幂等、可重试）、身份绑定 |
| `apps/api/src/health/`、`config.ts`、`bootstrap.ts`、`main.ts`、`prisma.service.ts`、`common/zod.ts` | 启动、配置校验、健康检查 |
| Prisma 模型 `Tenant`、`User`、`ExternalIdentity`、`AiCall`、`NotificationDelivery`、`AuditEvent`、`ImportBatch` | 租户/账号/身份/AI 计量/通知/审计/导入记录 |
| `packages/model-adapters` | `ModelProvider`：OpenAI 兼容（DeepSeek/通义/Kimi/智谱/豆包预设）、重试、计量、Mock |
| `packages/workspace-connectors` | `WorkspaceConnector`：钉钉已实现；飞书/企业微信为计划；能力矩阵 + 测试 |
| `infra/` 全部 | 本机安装、隧道、凭证录入、云服务器一键部署、备份、更新、`preflight.sh` |
| `.claude/skills/` | 交付流程技能 |
| `apps/web/src/api.js` 的登录/会话部分 | 前端薄适配层 |

## 样板业务（按新 Demo 替换）
| 位置 | 样板内容 | 替换成 |
|---|---|---|
| `input/demo/` | 已清空 | 新 Demo 原件 |
| `packages/domain/legacy/` + `apps/web/src/` 同名文件 | 电商核算引擎、导入器（`legacy-sync` 测试保证两处一致） | 新 Demo 的纯计算代码；没有就删掉这对目录和 `legacy-sync` 测试 |
| `packages/domain/src/briefing.ts` | 月度经营简报：事实表、状态机、AI 输出 schema | 新闭环的“系统事实 → AI 草稿 → 审批”状态机 |
| `packages/domain/src/roles.ts` | 老板/财务/只读 + 权限矩阵 | 客户确认的角色和权限（结构保留） |
| `apps/api/src/briefings/` | 简报接口 | 新闭环接口 |
| `apps/api/src/dataset/`、`imports/` | 11 类电商表的导入和数据集 | 新 Demo 的数据表（导入校验、事务写入的写法可照抄） |
| Prisma 模型 `Store`…`Invoice`、`Briefing`、`BriefingVersion` | 电商财务业务表 | 新业务表；写新迁移，不改样板旧迁移的历史 |
| `apps/api/src/seed.ts` | 虚构品牌数据 | 新 Demo 的演示数据（正式客户不跑种子） |
| `apps/web/src/` 其余文件 | Demo 页面 | 新 Demo 页面（保留原视觉） |
| `apps/api/test/`、各包 `test/` | 样板业务测试 | 保留租户隔离/权限/审计/通知类测试的写法，换成新业务 |

## 替换顺序（每步都保持 build + 测试通过）
1. 新 Demo 放进 `input/demo/` → 出映射表和待确认事项。
2. 换 `packages/domain`（计算 + 状态机 + 角色），补单元测试。
3. 换 Prisma 业务表 → 新迁移（开发库可重建；不碰任何生产库）。
4. 换 API 业务模块和种子数据，补集成测试（租户隔离、权限、审计必测）。
5. 换前端页面，接 `api.js`。
6. 删除不再用的样板业务文件，`git grep` 确认没有残留的样板业务词。
