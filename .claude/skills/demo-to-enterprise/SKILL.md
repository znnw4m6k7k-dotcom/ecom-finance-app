# Demo → 企业可上线应用（总控）

样板仓库：`github.com/znnw4m6k7k-dotcom/ecom-finance-app`（电商财务，已在钉钉真机验收）。新项目从样板复制，不从零写。
每一阶段结束都向用户报告：已做、真实执行的命令和结果、待用户/客户提供的东西。阶段门没过不进下一阶段。

## 0. 开新项目（自动）
1. 确认输入：DSH 项目目录（含 HTML、`.delivery/` 验收合同和 QA 结果，若有）。没有 Demo 就停下问。
2. 在样板仓库里运行：
   `bash infra/new-project.sh <目标目录> --slug <英文项目名> --tenant <演示企业代码> --scope <npm 前缀> --title "<中文名>"`
   它会复制通用骨架、改名、重置 docs/ 为空模板、清空 `input/demo/`，并 `git init`。
3. 把 Demo 原件放进新项目 `input/demo/`（不改原件）。新仓库要建在 GitHub 上时，由用户自己创建空仓库并告诉地址。

## 1. 需求映射（自动，产出给用户看）
- 按 `demo-import` 技能做：页面清单、按钮/表单、写死数据、浏览器存储、离线计算、外部依赖。
- 输出 `docs/Demo映射表.md`（✅/🟡/⛔）和 `docs/待确认事项.md`。
- 必问并记进待确认事项（用户不答就按“当前做法”继续，但不当作业务真相）：
  本期唯一业务闭环是什么；AI 在闭环里写什么（只能是草稿）；角色和审批人；用哪个办公平台；
  客户自选哪家国内模型；部署在谁的服务器；数据量级。
- **阶段门**：用户确认闭环和角色。

## 2. 设计审查与最小实现（自动）
- 先看 `template/样板说明.md`：哪些文件是通用骨架（登录/租户/权限/审计/模型适配/连接器/部署脚本，直接保留），哪些是样板业务（核算、简报、导入表，按新 Demo 替换）。
- 能复用的 Demo 计算代码放 `packages/domain`，前后端一份；口径改动要补测试。
- 新业务表写 Prisma 迁移；每个接口都有身份校验、租户隔离、角色权限；重要写操作写审计。
- AI 只生成草稿，数字来自系统计算；结构化输出校验、失败兜底、成本计量。
- 前端保留 Demo 视觉，只加 `apps/web/src/api.js` 薄适配层。
- **阶段门**：`npm run build`、`npm run typecheck`、`npm run test:unit`、`npm run test:api` 真实执行通过（没跑就写“未执行”）。

## 3. 连接器（自动写代码，联调要客户）
- 按 `connector-dev` 技能。本期只实现客户选的一个平台；其他两家保持“接口 + 能力矩阵”。
- 平台差异和联调步骤见 `client-onboarding` 技能的资料清单模板。

## 4. 客户资料清单（自动生成，人工发送）
- 按 `client-onboarding` 技能生成 `docs/客户资料清单.md`：每项写谁提供、去哪拿、是否密钥、怎么交付。
- 清单发给客户是对外发送，**由用户本人发**。密钥一律不经聊天，由客户在服务器上运行录入脚本。

## 5. 上线部署（脚本自动，执行要人）
- 按 `go-live` 技能：测试环境（本机 + 隧道）→ 正式环境（客户云服务器 + 备案域名）。
- 每次部署前后都跑 `bash infra/preflight.sh`，它按踩坑清单检查环境，不打印任何密钥。
- 买服务器、买域名、录凭证、正式发布、生产迁移：只给步骤和回滚方案，等用户/客户执行或批准。

## 6. 验收与交接
- 按 `release-review` 技能出里程碑报告；真机验收由用户或客户操作，报告里写明“谁在什么设备上验证了什么”。
- 新踩到的坑补进 `.claude/skills/go-live/references/踩坑清单.md`，能自动检查的补进 `infra/preflight.sh`，并同步回样板仓库。

## 不做
- 不把 Mock 说成已接通；`isMock=true` 的模型/连接器界面和审计都显示“模拟”。
- 不替客户付费、不保管客户密钥、不读员工私聊和通讯录、不自动生产部署。
