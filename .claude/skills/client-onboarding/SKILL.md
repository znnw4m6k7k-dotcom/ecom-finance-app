# 客户资料清单与收集流程

## 生成清单
1. 先确认三个选择（写在 `docs/待确认事项.md`）：办公平台（钉钉/飞书/企业微信）、模型厂商、部署位置（我方测试机/客户云服务器）。
2. 复制 `references/资料清单模板.md` 到项目 `docs/客户资料清单.md`，**删掉没选的平台段落**，把项目名、企业代码、回调/首页地址等占位符换成实际值。
3. 每一项保留四列：谁提供、去哪拿、是否密钥、交付方式。是否密钥的判断见模板顶部规则。
4. 平台后台的菜单名、权限名会改版：写清单前核对该平台当前官方文档，清单里注明“以后台当前显示为准”。

## 收集流程（五步）
1. **发清单**：用户（不是 Claude）把清单发给客户联系人，并约好企业管理员的时间（建应用、开权限、发布版本都要管理员）。
2. **非密钥资料**（CorpId、AgentId、域名、服务器 IP、人员名单、样例数据）：客户直接填进清单或发给用户，Claude 更新 `docs/客户资料清单.md` 的状态列。
3. **密钥**（App Secret、机器人加签、模型 API Key、数据库密码、SSH）：不发聊天、不发邮件、不截图。客户运维在服务器终端运行录入脚本（`infra/set-dingtalk-app.sh` 等，输入不回显，自动检查填错位），只写进权限 600 的 `.env`。
4. **核对**：运行 `bash infra/preflight.sh`，只报告“已填/缺失/格式可疑”，不显示值；把结果更新到清单状态列。
5. **收齐**：所有“必需”项为 ✅ 后，才进入 `go-live` 的联调步骤；缺的项在回复里列出并写明找谁要。

## 规则
- 任何人把密钥贴进聊天或截图，立刻提醒到平台后台**重置**，并在清单里记一笔。
- 绑定员工账号只用管理员提供的名单和员工本人打开应用时显示的 userid，不读通讯录、不读私聊。
- 数据发给模型厂商、数据出境、服务器放境外：标为“需客户法务确认”，没确认不上线。
- 飞书、企业微信若仍是“计划”状态，清单里要写明“本期需先开发连接器”，不要让客户先去建应用空等。
